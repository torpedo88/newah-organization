<objective>
## Goal

Bring the audited application scaffold from branch `phase-01/foundation-scaffold` onto the current branch, prove every inherited claim by re-running verification from scratch, and deploy it to Vercel behind a crawler block.

## Purpose

Phase 1 exists to prove the stack end to end and make the data layer safe before any community data exists. The scaffold half of that work was already built and hardened by an enterprise audit that found three genuine defects. Rebuilding it from scratch would discard that hardening and risk reintroducing the same bugs; restoring it costs minutes and preserves the fixes. What restoring must not do is import confidence — every acceptance criterion is re-verified here as if the code were new.

## Output

- 26 application files restored onto the current branch
- A green CI run on the pull request
- A live Vercel deployment serving a placeholder page that crawlers are told to ignore
- `.paul/` untouched — the SEED-derived project state is authoritative
</objective>

  <name>Task 2: Re-verify every inherited claim from scratch</name>
  <files>(no files modified unless a verification fails)</files>
  <action>
    Restored code is inherited, not trusted. Run each check fresh and read its actual output — do not cite the prior session's results, and do not treat "it passed before" as evidence.

    1. `pnpm lint` — expect exit 0
    2. `pnpm typecheck` — expect exit 0
    3. `pnpm build` with placeholder env vars set inline — expect exit 0

    8. Committed-tree secret scan:
       `git ls-files -z | xargs -0 grep -nIiE "eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}|sb_secret_[A-Za-z0-9]{8,}|sb_publishable_[A-Za-z0-9]{8,}|(service_role|anon)[\"']?[[:space:]]*[:=][[:space:]]*[\"']?eyJ|postgres(ql)?://[^[:space:]]*:[^[:space:]]*@" || echo CLEAN`

    10. Serve the build and confirm `/robots.txt` returns `User-Agent: *` with `Disallow: /`

Both are expected symptoms of that mismatch and are not failures. They are also the reason the pin exists.
